# Competitors

One file per competitor, named after them. Same rule as the rest of `docs/market/`:
**every claim is marked verified or assumed.**

A competitor note exists to answer two questions and no others:

1. **What do they already do that we planned to build?** Those stories stop being
   differentiators. Build them adequately, not well — you cannot out-build a shipping
   product on its core feature with a side project.
2. **What do they not do?** That is where the wedge is, if the field evidence agrees.

What these notes are **not** for: reassurance, feature-for-feature comparison, or deciding
we are doomed. A competitor validates that the problem is real. The question is only
whether we are solving a *different* part of it.
